== Machine-checkable contract

`CStoreArtifactAudit` rejects incomplete or empty bundles and verifies all of the following from structured JSON and emitted RTL:

* portable metadata filenames with no developer-specific output path;
* operation capabilities exactly `INPUT`, `OUTPUT`, `LOAD`, `STORE`, and `CSTORE`, with no CLOAD;
* generated CSTORE `OPC=4`, three operands, zero results, and latency 1, all matched against the current generator's initialized `OpInfo` contract;
* conditional IOB mode 2, three logical operands, six physical inputs, and explicit capability metadata;
* `IsStore`, `UseAddr`, and `UseEn` configuration IDs 17, 18, and 19, with `UseEn` at aggregate bit 127;
* each physical input pair -> operand mux -> three-lane SharedDelayPipe -> IOController input 0/1/2;
* top-level connectivity to all six IOB input ports;
* emitted RTL traces `io_in_2[0]` through `runtimePredicate`, `writeAllowed`, `writeEnable`, SRAM enable, and the registered write mask.

The generation test creates two independent bundles and compares the canonical hash of all four JSON contracts.
It also verifies that every checked-in JSON raw hash equals both the manifest entry and the fresh generated summary.

The default `tram.vitra.VerilogGen` was separately rerun into `/tmp/vitra-task4-default-sram.VGXx52` and exited 0 in 86 seconds.
Structured queries confirmed mode 1, two logical operands, four physical IOB inputs, no `UseEn`, no CSTORE/CLOAD, and the legacy `INPUT/OUTPUT/LOAD/STORE` capability set.

== Hardware and legacy regressions

Before the generator checkpoint, the complete fdra test command was:

[source,shell]
----
sbt -java-home /usr/lib/jvm/java-11-openjdk-amd64 -batch \
  "project fdra" \
  "set Test / parallelExecution := false" \
  test
----

It completed 33 tests in 5 suites with 33 successes and zero failures in 247 seconds.
This includes the Task 3 memory oracle:

* predicate 0: old memory value preserved, `sram.en=0`, `sram.we=0`, and `done=1`;
* predicate 1: exactly one `sram.en=1`, `sram.we=0b11` write replaces OLD with NEW;
* alternating predicates at II=1 write only true iterations while counters and completion progress;
* `UseEn=0` normal STORE ignores operand 2;
* normal LOAD remains independent of predicate;
* independently delayed data/address/predicate streams realign at the IOB controller;
* active FIFO STORE/LOAD and default SRAM routed-address STORE/LOAD smoke tests pass.

The final post-documentation regression completed 35 tests in the same 5 suites with 35 successes and zero failures in 233 seconds.
It includes the manifest writer and the checked-in JSON/generation hash binding in addition to every checkpoint test above.

== ADORA read-only parse smoke and blocker

The checked generator output was passed directly to the existing ADORA Mapper without modifying either repository:

[source,shell]
----
printf 'module {}\n' | \
  /home/jyhu/adora-compiler/build/bin/cgra-mapper \
  --adg=<fresh-output>/spec/vitra_cgra_adg.json \
  --op-file=<fresh-output>/spec/operations.json \
  --output-type=pytest --obj-opt=false \
  /dev/stdin --output=/dev/null
----

The command exited 0 and reported `Parse Operations`, `Parse ADG`, 240 GPE nodes, 48 IOB nodes, and 8 tiles.
This establishes schema/read compatibility only.

Trusted capability consumption is explicitly *blocked* in the current external ADORA checkout.
`mapper/src/ir/adg_ir.cpp:148-154` ignores the artifact's precise IOB `operations` array for `COND_LS_MODE` and injects both `CLOAD` and `CSTORE`.
The smoke output consequently printed `operations: CLOAD, CSTORE, INPUT, LOAD, OUTPUT, STORE` even though VITRA's truthful generated operation catalog and IOB attribute intentionally omit CLOAD.

Task 4 does not modify ADORA and does not implement CLOAD to mask this consumer defect.
The artifacts remain suitable for schema parsing and for a future ADORA reader that trusts the explicit capability metadata.
